# CONNECT FOR BRANDS partner console — module author guide

Product: a Stripe-quality self-serve console for **partners** (manufacturers/distributors of IoT devices: inverters, GPS trackers, alarms, boiler relays…).
The partner registers, creates brands → categories → device models, uploads IMEI whitelists, orders **Activation Keys** and **Service Tokens** from OTA TECHNOLOGY DMCC (Tax Invoices in USD, or EUR for countries in Europe), receives **SIM cards in custody** (one per key bought for the country) via shipments, manages SIM inventory, generates activation codes and hands them to resellers (installers, shops, branches), and plans revenue.
We (OTA) set the plan per model (Light / Standard / Premium) and the per-country price lists. In the demo this is done in **"OTA mode (demo)"** (`S.admin === true`, toggle in the sidebar). Show admin-only controls only when `S.admin` and mark them with `ui.note('admin', …)` or the violet badge so the demo audience understands they're our-side actions.

- Your module: `src/modules/<NN>_<name>.js` (and optional `src/modules/<NN>_<name>.css`). Do NOT edit `src/01_core.js`, `src/02_shared.js`, `src/00_core.css`, `src/99_boot.js` or other agents' modules. If you need a core change, describe it at the end of your report.
- Build: `python3 build.py` → `index.html` + `bundle.js`. Check: `node --check bundle.js`.
- Smoke test: a static server already runs on http://localhost:8777 serving this folder (if not: `cd <console> && python3 -m http.server 8777 &`). Use Playwright (`require('playwright')`, chromium preinstalled; viewport 1280×800 and 390×844). Click `[data-act=demo]` on the signup page (or call `seedDemo()` via your own flow) to get demo data. Make sure: no `pageerror`, no horizontal overflow at 390px (`document.documentElement.scrollWidth - innerWidth <= 0`), all your routes render in uk/en/ru.
- All files are concatenated into ONE IIFE in this order: 01_core.js, 02_shared.js, modules sorted by filename, 99_boot.js. Everything is a plain global inside that IIFE. Top-level names must not collide: prefix every top-level function/const in your module with your module prefix (e.g. `cat_`, `ord_`).

## Quality bar ("Stripe level")
- Clear page header with one primary action; summary before detail; tables with status badges, search/filter, pagination for long lists (50/page); empty states that explain the next step with a button; drawers for detail; inline validation with specific messages; toasts that say what happened ("Invoice CFB-2026-0005 marked as paid").
- Plain language for a busy business owner. No jargon where a normal word works. Never invent legal facts; placeholders in [brackets].
- Works at 390px width (tables scroll inside `.tblwrap`), dark mode via tokens only (never literal colors except brand colors the partner picks), keyboard accessible (real buttons/links/labels).
- Keep it fast: S.sims can be thousands, S.codes thousands — paginate and avoid O(n²) loops in render.

## Business rules (shared truth) — commercial model v09 + legal pack v10, updated to pack v12 (v12 wins where they differ)
- **Seller & currency (v12, MPA 8.1)**: OTA TECHNOLOGY DMCC invoices the partner in the **currency of the country's Order Form**: USD, or **EUR for Approved Countries in Europe** (demo: UA, KZ = USD, **DE = EUR**). That currency applies to all prices, invoices, credit notes, Statements, commission invoices and payments for the country. Source: `S.ota.countries[CC].currency` (`'USD'|'EUR'`, default EUR for EU members, else USD); read it ONLY through **`ccy(cc)`** (alias **`cur(cc)`**). Money: `moneyCc(n, cc)`, `money(n,'EUR')` (→ `€1,234.50`; USD → `$…`), stored documents `docCcy(doc)` (their frozen `currency`), mixed totals `moneyByCcy([[amount,cur],…])` (never adds across currencies). The currency of a country is locked once it has invoices or statements (`ccyLocked(cc)`). `S.ota` data is frozen into each invoice as `inv.seller`; EUR invoices are paid to OTA's EUR account (`OTA_BANK_ACCOUNT_EUR`, `OTA_BANK_IBAN_EUR`, fictional demo values). `S.org.currency` is legacy (catalogue).
- **What is sold**: **Activation Keys** ("copies of the CONNECT computer program (licence activation keys)", one per device for life, bought per Approved Country; **v12: for each key bought for a country OTA provides one SIM for that country in custody, free — keys and these SIMs are shown as ONE batch**, see SIM shipments) and **Service Tokens** (plan × term: Light/Standard/Premium × 12/24/36/48/60 months; valid **36 months from issue**; exchangeable). **SIM cards are never sold or invoiced.**
- **Prices**: per-country, versioned `S.priceLists[CC]` (net, in `ccy(cc)`; each version stores `currency`): key price, tokens 3×5, OTA Retained Amount per paid month (3 plans), compliance fee 0–3%. Seed (LEGAL_SPEC §1): UA key $9.85, tokens = (75 / 99 UAH ÷ 1.2 ÷ 45.0564) × months × (1 − disc), disc 12m 10%, 24m 20%, 36m 30%, 48m 35%, 60m 40%; Premium = Standard × 1.5; retained = monthly net wholesale. KZ: key $9.40, 990 / 1 290 KZT ÷ 1.16 ÷ 441.77. **DE (v12): key €8.90, tokens = (3.99 / 4.99 EUR ÷ 1.19) × months × (1 − disc), Premium = Standard × 1.5, retained = monthly net (€3.35 / €4.19 / €6.29)** — same figures as `LEGAL_DEMO_VALUES.countries.DE`. Fee 0%. Any increase (price, retained, fee) is effective **≥ 90 days** after the change (`plAdd` clamps `from`); decreases from the chosen date. **v10 (ТЗ 3.2):** key / token / retained prices may not rise more than **10% in any rolling 12 months** (base = lowest value in force during the 12 months before `from`; `plIncreaseCheck(cc,data,from)` → `{increase,minFrom,noticeOk,cap:[…]}`; `plAdd` returns `{err:'cap'}` and saves nothing; `plCheckVersion(cc,ver)` re-checks a version before its Order Form version is issued). An increase needs a **justification** (supplier / regulatory cost growth) and a **document link** (`v.justification`, `v.docLink`; UI passes `strict:true` → `{err:'justification'}` if missing; non-strict callers get `v.justMissing`). The fee (0–3% rate) counts as an increase for the notice but is not measured against the 10% cap. An increase never applies to keys, tokens or subscription periods already paid (invoices/lots freeze unit prices and `priceVer`). A new version withdraws still-pending ones. Orders/drafts are priced from the version current when the invoice is issued.
- **Orders**: a checkout creates a **Key order** (`K-0001`) and/or a **Token order** (`T-0001`) for one country, on **one combined invoice or two**. Minimums per partner (`orgMin()`): first key order ≥ 1 000 keys, later ≥ 100 (OTA edits on Prices). Tokens only for plans assigned to approved models. Drafts (no invoice, no number used) can be deleted; issued orders are cancelled via a **credit note**. `orderBlock(cc)` (HOOKS.orderBlock) can block a country. A price-changed Order Form blocks only its own country after the effective date (legal module). **v10 (ТЗ 3.5):** instead of signing, the partner signatory may **terminate the Order Form for that country** (`ofTerminate(cc,{priceVer,note})` → notice `{type:'of_terminate'}` in `S.notices`, `S.org.ofTerminated[cc]`, audit `orderform.terminate`); new orders for that country are then blocked (core orderBlock hook), other countries unaffected.
- **Invoices** (`mkInvoice`, template 13): "TAX INVOICE", number `OTA-INV-YYYY-NNNNNN` (global), currency `ccy(cc)` frozen as `inv.currency`; header "Registration no. {OTA_REGNO} · Licence no. {OTA_LICENCE}" (service licence only, demo values fictional) + TRN; lines exactly "Activation Keys – copies of the CONNECT computer program (licence activation keys) – {Approved Country}" and "Service Tokens {Plan}, {term} months". **VAT (v12, MPA 2.6):** ONE VAT line — **5% ("VAT 5%")** if the partner is resident, VAT-registered or has a fixed establishment in the **UAE**, otherwise "VAT 0% – zero-rated export of services" (a partner in another GCC state: 0%, it accounts for its own tax). **`vatRateFor(org)` → 5 | 0 (percent)**; `vatInfoFor(org)` → `{rate:0.05|0, pct, ae, reasons:['incorporated'|'resident'|'vat_registered'|'fixed_establishment'], src}` reading the legal module's `S.form` keys `P_INC_COUNTRY`, `P_TAX_COUNTRY`, `P_VAT_REGS` (free text; "AE…"/TRN token = UAE, "none"/"no" ignored), `P_UAE_FE` (yes/no), fallback `P_COUNTRY` / `S.org.country` / `S.org.taxCountry` / `S.org.vatRegs` / `S.org.uaeFe`. `invVat()` uses it; `inv.vatRate` (0.05|0), `inv.vat`, `inv.total = net + vat`, `inv.vatReasons`. The AED line is ALWAYS printed: "VAT amount in AED at the UAE Central Bank rate {AED_RATE} on the invoice date — AED {vatAed}" with the real amount `inv.vatAed = vat × rate` (0.00 at 0%). The rate is the CBUAE rate **of the document currency**: `S.fx.aed` rows `{date, usd_aed, eur_aed, src}` (demo 3.6725 / 4.2725 'CBUAE (demo)'), edited by OTA Finance `ota.vat` on the Invoices page in OTA mode (USD and EUR inputs), `aedRate(date, cur='USD'|'EUR')`, `aedRateSet(date, rate, src, cur)`; stored with the document (`inv.aedRate`, `inv.aedRateDate`, `inv.aedSrc`, `inv.aedCur`). Statuses `open → paid | cancelled`; overdue is derived (`invStatus`). Partner can report "I've paid".
- **Issue after payment**: only **OTA Finance** (`can('ota.payments')`) marks paid → `invoicePaid()` creates key lots / token lots and completes exchanges automatically. Nothing is issued before.
- **Tax Credit Notes** (template **13A** `LEGAL_TPL.CN`, `OTA-CN-YYYY-NNNNNN`, global counter, never reused — also across demo resets): `creditNote(inv, reason, {settle})`, reason ∈ `CN_REASONS` = `cancel_unpaid` (unpaid only) | `error` | `refund` (paid only) with the ТЗ 2.3 EN/RU texts. Lines = invoice lines (stored negative in `cn.lines`; the print template gets unsigned amounts and prints "–"), the invoice's currency and VAT rate (`cn.vat`, `cn.total = net + vat`, `cn.vatRate`), "VAT adjustment in AED at the UAE Central Bank rate {AED_RATE} — AED –{vatAed}" (rate of the CN date in the CN currency stored in `cn.aedRate`, `cn.vatAed`). Unpaid source → invoice `cancelled`, no keys/tokens ever issued under it (`invoicePaid` refuses). Paid source (only while none of its keys/tokens is used) → lots revoked, `cn.settle` = `refund` (to partner's bank) | `setoff` (next order). Shape `{id,number,invoiceId,invoiceNo,invoiceDate,cc,currency,lines,net,vat,vatRate,vatAed,total,aedRate,aedRateDate,reason,reasonNote,wasPaid,settle,createdAt,by}`. Invoices are never deleted.
- **Numbering (ТЗ 2.1):** RS per country `OTA-ARV-RS-UA-202611`; INV/CN global; PF/SR same NNNN; partner commission invoice uses the partner's numbering and may reference **one or more statements of several countries of the month** ("per Statement(s) …", `ci.rsIds` / `ci.rsNos`, template key `RS_NO`). **v12:** a commission invoice combines only statements **in the same currency** (`ops_ciPeers`); statements and commission invoices carry `currency` (DE: EUR).
- **Settlement deadlines (ТЗ 2.8, MPA 8.2):** OTA statement by the 10th, partner invoice by the 15th, payment of undisputed invoices by both by the 20th; a statement without the partner's answer within 5 business days is confirmed automatically (`ops_autoConfirm`).
- **Activation (ТЗ 3.1)** — `deviceActivate(sim, {via:'token', code} | {via:'subscription', sub})`: the **Activation Key of the SIM's country** (`simCc(sim)` = shipment country; `consumeKey(cc)`, `keysAvail(cc)`) is consumed at activation (one per device for life). The plan comes **either** from a Service Token (the code: 1 token of the exact plan+term, soonest-expiring lot first) **or** from an **active Direct Subscription** (`S.subs[]` `{id,iccid,imei,plan,cc,status,startedAt,paidUntil,autoRenew,src:'card'}`, `subCreate`, `subActive`) — then no token is used. No key → rejected (`no_key`), code stays valid. Codes redeemed in the customer portal (bridge `cfb-demo-ownership.codes[CODE].status='redeemed'`, `device_id` = IMEI) are activated by `cx_bridgeSync` with the same rules. Expired tokens are shown but unusable. A code's plan must match the model's plan; only approved models.
- **Service Tokens per country (v12):** token lots carry `cc` (bought on that country's invoice, in its currency); a device uses tokens of its SIM's country only (`consumeToken(k, cc)`, `tokensAvail(k, cc)`, `tokenStats(k, cc)`); stock is shown per country (order form, Orders KPIs, `#codes` cards); exchanges stay within one country (`exchangeCreate(from,to,qty,cc)`).
- **Invoice / credit-note pages** (`#invoice--id`, `#cnote--id`) render the document from template 13 / 13A (`ops_build`, EN + RU as in the template, never the UI language); the copyable payment details are a separate UI card.
- **Exchange** (`exchangeCreate`): N tokens A → B (same validity). More expensive → difference invoice (`kind:'exchange'`, line type `xchg`), tokens reserved until paid; cheaper or equal → immediate, no refund.
- **SIM shipments in custody — only from the EU (ТЗ 1.2)**: SIMs never enter or transit the UAE. Each shipment has `ship_from{name,addr,country (EU)}`, `ship_from_country`, `exporter{name,eori}` (EU exporter of record acting for OTA; demo values fictional). PF (11) shows "Owner of the goods: OTA TECHNOLOGY DMCC" (no TRN), ship-from address, exporter + EORI, country of dispatch / destination; A2 box label print view `#opsdoc--a2--id` shows "SHIPPER (OWNER OF GOODS) — OTA TECHNOLOGY DMCC" + SHIP FROM block. **No Dubai Customs code** (`OTA_CUSTOMS_CODE` removed everywhere). Demo ICCIDs = `89380012` + 10-digit index + Luhn digit (19 digits, `genIccid`, `iccidIndex`). OTA Admin creates a shipment (qty, first ICCID, SIM type, customs unit value, DAP address/importer, ship-from, exporter/EORI) → `OTA-PF-YYYY-NNNN` + `OTA-SR-YYYY-NNNN` (same NNNN) → `prepared → shipped (carrier, waybill) → delivered → received`. Partner (Admin/Operations, `p.receipt`) confirms received qty, packaging condition, storage place, responsible person → SIMs enter `S.sims` (status `stock` = in custody) with `shipmentId`. Custody covers only uninstalled SIMs.
- **Activation Keys and SIMs 1:1 (pack v12, MPA 7.1 / 8.1, Doc 09 1.2, OF 2.1 / 4.1):** keys bought for a country (paid, not revoked key lots) = SIMs OTA owes for that country (`simEntitled(cc)`); **one batch per key lot** = N keys + N SIMs (`simBatches(cc?)` → `{cc, orderNo, invoiceNo, issuedAt, keys, keysUsed, keysFree, sims, simsShipped, simsToShip, revoked}`, shipped SIMs allocated to the oldest lots), shown on `#shipments` (card "Activation Keys and SIM cards 1:1", per-country progress) and `#codes`. `simQuota(cc)` → `{entitled, shipped (incl. transit), delivered, transit, activated (keyed, of delivered), stock, pct = activated / delivered, left = entitled − shipped, ok70, need, canShip, reason:''|'no_keys'|'quota'|'70'}`. Rule: SIMs ship only within the keys bought; **a further shipment needs ≥ 70% (`SIM_NEXT_PCT`) of the SIMs previously delivered for that country activated** (delivered = shipments `delivered`/`received`, received qty; SIMs in transit do NOT count; activated = activated in CONNECT with an Activation Key, i.e. the SIM holds `keyLotId`), "unless OTA agrees otherwise" → OTA Admin ticks the exception with a mandatory note (`override:{note}`, stored in `h.rule.override`, audit `shipment.create` details `override70` + `overrideReason`, plus `deliveredBefore`, `activatedBefore`, `activatedPct`). The quantity cap cannot be overridden. `shipCheck(cc, qty, override)` → `''|'no_keys'|'quota'|'70'`; `shipCreate(o)` returns `{err, quota}` when blocked (`o.force` only for seeds); each shipment stores the snapshot `h.rule = {entitled, before (delivered), transit, activated, pct, ok70, override}`.
- **Germany (DE, v12 demo):** EUR price list, OSS no. `S.ota.countries.DE.oss_no` (fictional `EU276DEMO01`, key `OTA_OSS_NO`, `otaOss(cc)`; editable on `#requisites` → Countries), paid key + token order K-0004 / T-… (one batch 300 keys + 300 SIMs), shipment of 200 SIMs from the EU warehouse to Hamburg (received), 150 activated with a key of 200 delivered (75% → a further shipment of up to 100 allowed; UA is the blocked example: 226 of 1,000 = 22.6%), 90 activations by codes of installer r5 using DE (EUR) tokens, 60 Direct Subscriptions (cc `DE`, EUR), statements and commission invoices in EUR. Bridge SIM records carry `cc:'DE'` (80_ownership `own_simRec`).
- **Direct subscriptions**: commission = Net Collected Revenue (minus OTA taxes in customer country, acquiring, refunds, compliance fee) − OTA Retained Amount × paid months. RS by the 10th, commission invoice by the 15th (legal/ops modules). The calculator keeps local-currency retail and converts the country's wholesale currency (USD/EUR) × FX; for DE retail and wholesale are both EUR (no FX). Actual vs plan (`#actual`) is per country (calculator country), never mixing currencies.
- **Annual target** 3 000 activated devices (not a purchase obligation).
- IMEI whitelist, model plan review, SIM statuses `stock` / `active` / `blocked` as before; SIMs carry `keyLotId` once their device consumed a key.

## Print module integration (85_print, print ТЗ v1.4) — commercial side
- **`S.prn`** (owned by 85_print; others read only): `{brands:[brand versions, status draft|submitted|approved|superseded], plans:[{id,name,pkg,term,active,…}], batches:[{id,no,runId,runNo,brandId,brandVer,status:'generated'|…|'printed'|'closed',keyRes:[[lotId,k]…],downloads,blocks,…}], runs:[print release runs], csvLog:[…]}`.
- **Code contract:** new card codes are **12 Crockford Base32 characters** (`0-9 A-Z` without I L O U), shown `7K4M-9QXR-2HTD`, the 12th character is a Luhn mod-32 check (`prnCodeNorm` = upper-case, strip spaces/dashes, O→0, I/L→1; `prnCodeCheck`; `prnCodeFmt`). Each has its own 12-digit serial `1000 0000 0001` (`serial` display, `serialNo` number). Records in `S.codes`: `{code, serial, serialNo, batchId, planId, plan, term, cc, deadline, status:'generated'|'exported_for_print'|'printed'|'activated'|'blocked'|'expired', reseller, keyResLotId, createdAt, activatedAt, iccid, voidAt, …}`. **Only `printed` is redeemable.** Old 16-character codes (`parseCode`, status `issued|activated|void`, no `batchId`) keep working unchanged.
- **Activation:** `cx_tryActivate(raw, iccid)` (45_codes) routes 12-character input to `prnRedeem` (85_print) and maps its errors to neutral texts (`prn.rd.e.*`: used / blocked / expired / not yet printed / invalid); 16-character input follows the old path. `deviceActivate(sim,{via:'token',code})` consumes **the key reserved for the code** (`code.keyResLotId`, released from `reserved`/`prnRes`, `used++`) instead of a free key when it is still set; a device that already holds a key just frees the reservation. Tokens: the code's plan+term, of the SIM's country.
- **Key reservations:** each new code reserves ONE Activation Key of its country: `keyLot.reserved` (+1; honoured by `lotFree` / `keysAvail` / `keyStats().avail`; `keyStats().reserved`) and `keyLot.prnRes` (the print share of `reserved`). Released on activation, block or expiry. Helpers: **`keyReserve(cc, n)`** → `[[lotId,k],…]` (oldest lots first, all-or-nothing, `null` when fewer than n are free) and **`keyRelease(lotId, n=1)`**.
- **Bridge** (`cfb-demo-ownership.codes[CODE]` for a new code, written by 85_print `prn_bridgePush`): `{partner, serial (12 digits, no spaces), plan, term, cc, batch, deadline, format:'v14', status:'new' (printed) | 'redeemed' | 'blocked'}`. Portal redemptions of `format:'v14'` codes are activated only by 85_print `prn_fromPortal`; 45_codes `cx_bridgeSync` skips them (no double activation). `cx_stats` and the point-of-sale code lists skip codes with `batchId`.
- **Labels:** the A2 box label is 85_print's (`#prn-labels--<shipmentId>`); `#shipment--id` has a native "Print labels" button (`data-prn-lbl`, so 85_print does not inject a second one); `#opsdoc--a2--id` forwards there. PF and SR stay in 75_opsdocs.
